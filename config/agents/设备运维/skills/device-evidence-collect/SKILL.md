## 适用场景

**凡消息含 `ticket_id=` / `【BMS工单AI处理】` → 一律工单取证模式。**  
禁止声称「非工单场景 / 仅采集」；禁止用 `📋 设备` 非工单汇报模板。

- 工单**未命中**处置剧本 / 处置失败 → 由 `ticket-handling` 加载（取证；**写评改状态归编排，本技能禁止写评**）
- **禁止**本技能在有工单标识时自行 `create_ticket_comment` / `change_ticket_status`（一律交编排，防双发）

## 工单取证模式（无剧本 / 处置失败）
**谁写评论（防双发）：** 本技能**只取证**；`create_ticket_comment` / `change_ticket_status` **只由** `ticket-handling` 第五步调用（恰好 1 条）。

**当前态 ≠ 故障时刻（通用）：** 影子/刚下发的控制只说明「现在」；评论素材须对齐工单 **`happenTime`**（日志时间窗摘录或明确负结果；该类须 bag 则挂故障时刻包）。禁止只写实时状态就交编排结案。

**终端不可达 / 影子离线 / 设备未联网或关机：** 只陈述连通性事实（连不上、离线、无终端回显）。**禁止**据此推断模块崩溃、驱动挂死、内核异常等根因——没有工具日志原文就没有这类结论。

```
（已有）get_device_shadow
  → 按故障现象选产物：相关模块日志，和/或故障时刻录包 + 实时相机
  → 终端按「固定步骤」取证（需要日志时）
  → 需要录包时（行走/感知相关，或日志空）：find_bags_near_time → upload_bag_file → create_ticket_attachment
  → 行走/感知相关：**须** get_camera_image（相关方位 1～2 个）→ 有 url 则 create_ticket_attachment
  → 汇总摘录/负结果/已挂附件要点后结束本技能（disconnect），【禁止】create_ticket_comment / change_ticket_status
  → 交回 ticket-handling 第五步写评+改状态
```

**同一 `ticket_id` 本会话：`create_ticket_comment` `verified=true` ≤ 1**（由编排保证）。  
**有 `ticket_id` 时：只在对话里输出分析 ≠ 完成**（须交编排写评+改状态）。  
**评论/结论素材必须围绕工单 `faultList` 的码与名称**；影子里其它实时故障不得改写为主定位。  
**禁止「计划话术」收工：** 不得以「接下来我将… / 现在需要解析… / 让我再… / 命令已发送正在等待… / **正在处理中** / 继续执行…」作为最终回复或 `[done]` 正文；工具已返回（含非空 `ls`/`grep`）→ **立刻**再调工具继续取证或交第五步写评结案。  
**未完成判据（出现即禁止结束）：** 最终正文只有进度句、或未完成「时间窗抽行 →（行走类）bag/相机 → 交编排写评+改状态」却宣称处理中。  
**只使用本技能「允许的工具」**；未写明的接口一律不调（含 `set_control_mode` / 回桩 / 倒退 / 重启等处置类）。取不到证据须把尝试与原因写入交编排的结论素材。  
**禁止编造已远程处置**：无本技能允许且已成功的工具回执时，不得写「已切换自动模式 / 已下发…」。

## 禁止编造日志（零容忍）

写回工单 / 对用户汇报的任何「日志摘录」「关键时间点原文」必须满足：

1. **摘录 ⊆ 本会话工具回显**：该行（或连续几行）须为某次终端工具 `output` / `raw_outputs` 的子串；允许删行号前缀、截断过长行，**禁止**改写字段名、补全未出现的词、翻译成更「像日志」的英文/中文
2. **无回显 = 无摘录**：工具空输出、只剩命令回显、或只有刷屏噪声 → 评论写「已查路径/时间窗，无命中」，**禁止**用训练知识或「常见故障日志」填空
3. **skill 示例 ≠ 本机证据**：下文对照附录、关键词表、历史幻觉形态只指路；**不得**把示例句子复制进评论冒充本单摘录
4. **写评论前自检**：拟粘贴的每一行，能否在上一轮工具结果里对上？对不上 → 删掉或回去再查；对不上还写 = **流程违规**

负结果合法写法：`已 ls …；已对 …/_YYYY-MM-DD 抽 happenTime 窗；工具无匹配行。`  
非法写法：未见工具行却凭印象写一整句「日志原文」。

### 附录：历史幻觉形态（非穷尽、非禁词）

下列曾在错误评论中出现过；**不是永久黑名单**。若当次工具 `output` 里真有完全相同子串，可以引用；没有就**禁止**写进评论：

- 臆造来源字段/管脚/驱动前缀（如未见回显却写 `hardware_button`、`GPIO12`、`chassis_driver:`）
- 臆造目录（如未见 ls 却写 `/logs/chassis/`）
- 把训练里的「典型急停英文句」整句粘贴进评论

## 产物分工（行走 / 底盘 / 感知）

| 产物 | 用途 |
|------|------|
| 录包（happenTime） | 人工分析**为何触发**（传感器/底盘原始数据） |
| 实时相机图 | 人工看**当前四周/障碍物/现场情况**（不能代替故障时刻 bag） |

**行走/底盘/感知相关故障（有 ticket_id）硬契约：**
1. 日志可抽则抽；**须**按 happenTime 查录包；定位到切片 → **必须** `upload_bag_file` → `create_ticket_attachment`（1～3）
2. **须**再拉实时相机图：按产品取与现象相关的 1～2 个方位（不扫遍）→ 有 `url` → **必须** `create_ticket_attachment`
3. 影子已恢复可缩短终端探路，但 bag（有切片）+ 相机（须尝试）仍要走完再评论改 `3`
4. **禁止**只建议下载 bag / 只描述现场而不挂附件；未尝试相机或定位到包未挂 = **流程未完成**

**相机方位（合计 ≤2，失败记一句勿连环换）：**
- SC50/SW50：默认 `前`；防跌落/下视相关再加 `下`
- T810：默认 `前`；需看四周再补后/左/右之一

**日志空/未命中时间窗：** 补拉录包并挂附件（有则挂），行走/感知仍须尝试相机挂图，再写评论。  
**录包查询：** `find_bags_near_time` 无结果 → **至多再** `list_device_bags` **1 次**；仍无则评论写明，禁止反复 list。

## 取证边界原则（通用）

所有终端/录包取证必须遵守下列原则（适用于任意故障类型，不按个案补丁）：

| 原则 | 含义 |
|------|------|
| **时间锚定** | 一切日志证据必须对齐 `happenTime`；**优先抽时间窗原文**，关键词只作辅；禁止读文件末尾；禁止打开与故障时刻无关日期的日志 |
| **有界探测** | 找到当日文件后**优先时间窗抽取**，勿反复 `ls` 空转；同一命令最多 2 次。**运行时工具闸：禁 tail/cat、大日志 grep 须 head、同命令去重**（不做总条数硬封顶，避免「已找到文件却抽不了」） |
| **换维不停** | 同一维度（同目录、同命令变体、往回翻日期、只换关键词）连续失败 → **换候选路径/模块**或**停**；禁止在同一维度上加深 |
| **产出契约** | 每轮后须给出**时间窗摘录**或明确负结果（该窗无行/无当日文件）；禁止连续探路叙事、零产出；禁止用空关键词断言根因 |
| **候选上限** | 日志候选 **≤3 个**；按**故障域**选**主查 + 辅查**（见日志路径）；每个至多 1 次有效时间窗抽取；用尽 → 停终端 |
| **负结果即完成义务** | 已对主查/辅查做过 happenTime 时间窗（含空命中）→ **时间窗义务已完成**；不得因「未找到根因」继续扫模块/`tail`/影子。立刻交编排写负结果评 + 改状态 |
| **收尾阶梯** | 终端无果 → 查录包（有切片则 upload 挂）→ **行走/感知再拉相机挂图** → 写评论 → 改状态；影子已恢复可缩短探路，已定位的包与有 url 的图仍须挂 |

## 终端取证固定步骤

取证目标是**围绕 happenTime 抽「时间线附件」作证明**（该时刻前后日志原文），不是关键词扫盘、也不是整机诊断。

1. **先 `ls` 一次日志根（全量）**；再对选定模块查**当日文件**（勿用 `ls | head` 被旧文件挤掉当日）：  
   - 例：`ls /opt/xzrobot/logs/xzrobot_driver2/ | grep 2026-08-07` 或直接测 `_2026-08-07` 是否存在  
   - 勿猜 `模块_日期.log` / `/logs/chassis/`（SC50 实机**通常无** `chassis/` 目录）
2. 按故障域选**主查 + 辅查**；路径/文件名**只能**来自 `ls` + 默认 app
3. **主抽 = 时间窗**，但要能落到故障行：  
   - 先用 happenTime ±1～3 分钟的时间串过滤（格式随实机，如 `[2026-08-07 10:43:`），且 **必须** `| head -n 20`（或等价封顶）  
   - 若窗内被同质刷屏淹没（如大量 `Command velocity timeout`）→ **同文件再滤一刀**（时间串 **且** 域关键词，或把时间窗收到秒级）；**「一次有效时间窗」= 时间串抽行 ± 同文件至多 1 次降噪**，之后必须换候选或收尾，**禁止第三刀**  
   - `head` 勿截在刷屏前就停；刷屏时必须做上述降噪，**禁止**把刷屏当「已取证」也**禁止**因此放弃主查并去扫无关模块
4. **关键词为辅**：只在已确认的当日文件上；**禁止**一上来全库 `grep fall`、空了就编 `chassis/`/`peoception`
5. **评论摘录 ⊆ 当次工具回显**（见上方「禁止编造日志」）；无回显不得凭印象补英文/中文套话
6. 有合格摘录 → 交编排写评（可再补 bag/相机）；时间窗+降噪仍空 → **记负结果**，换下一候选（≤3）或收尾；禁止 `tail`/`cat` 全文；**不得**因未找到根因无限换目录
7. 主查目录在根 `ls` 中存在却未抽到当日文件/未做时间窗 → **流程未完成**；**已做时间窗且空命中 = 义务完成**（不是未完成）
8. **交编排写评前**：对拟写入的每条摘录做一次「是否出现在工具 output」核对；任一不过 → 禁止交给编排写进评论

### SC50 急停实机形态（对照附录，勿当万能模板）

- 目录：主查常为 **`xzrobot_driver2`**（按日文件 `_YYYY-MM-DD`），**不是**臆造的 `/logs/chassis/`
- 子目录：可能有 **`xzrobot_driver2/lora_logs/`**（偏工作站/对桩 LoRa）——对桩/回站可辅查；**普通急停不必默认深挖**
- 行内 logger 名可能是 `[/xzrobot_chassis]`（这是**日志字段**，不是目录名）
- 有效证据须来自当次工具回显（常见形态仅供认路，如 MCU `emergency =1/0`）：只证明该时刻急停状态置位/清零，**不等于**已证实物理按键
- **辅查默认 app**：SC50 急停常在 app 有上报行；须对默认 app 做 happenTime 时间窗（目录 ls 存在时）。**禁止**把某次固定句式（如特定 Trigger Fault 文案）当成每单必抄摘录
- 急停通则（各产品）：按上方故障域表对**主查 + 默认 app**分别做时间窗（ls 有则做）；以当次回显为准，勿把本对照段整段套到 T810/其它域

### 硬约束：候选只能来自实况 + 故障域

| 禁止 | 必须 |
|------|------|
| 先猜 `mcu`/`can`/`chassis/`/`safety/`/`peoception` 再探测 | **先全量 `ls`**；只进回显目录 + 默认 app；SC50 感知常见 **`visual_perception`** |
| 把 **bag 的 2 分钟切片** 套到模块日志 | 文件名只来自模块目录 `ls`；bag 惯例仅用于录包 |
| `ls \| head` 没看到当日文件就说「无当日日志」 | 对 happen 日期 `grep` 文件名或直接测 `_日期` |
| 时间窗只有刷屏、或只做关键词空结果就换臆造路径 | 同文件：**时间窗 → 降噪（时间∩关键词或收窄秒）** |
| 工具 output 没有的句子写进评论当「日志摘录」 | **摘录 ⊆ 工具回显原文**；写评论前逐行核对 |
| 把 skill「示例形态」当本单证据粘贴 | 示例只指路；本单摘录必须来自当次工具 |
| 空日志 + 无 bag + 相机错码 →「硬件根因已证实」 | 只陈述步骤与负结果 |

- **尽量带上故障发生时间**（工单 `happenTime` / 用户给出的时刻）；取证围绕该时刻附近，而不是「现在」的文件末尾

## 终端登录

| 产品 | 用户 | 密码 |
|------|------|------|
| T810 / Titan810 / XZ-TITAN810 | `xzrobot` | `titan@810` |
| SC50 / SW50 等 | `xzrobot` | 默认 `xzyz2022!`（现场可能不同） |

也可用环境变量 `TERM_USERNAME` / `TERM_PASSWORD` 覆盖。

**终端用法提示：**  
- SC50 偏慢 → **优先一次** `interactive_session`，同批带上：`ls` 日志根 + 主查目录当日文件探测 + 时间窗抽取（少轮次、少中途收工）；**建议 ≤4 条/批**，整批墙钟约 50s（对齐 MCP 超时）  
- 时间窗命令形态：`grep -a '\[2026-08-07 10:43:' FILE | head -n 20`；**禁止** `tail`/`cat`、禁止无 `head` 的全日 grep  
- **禁止** `send_command` 后再发「命令已发送，正在等待输出」并结束回合——工具返回即本轮结束；`output` 非空 = 已收到，必须基于回显继续（再抽日志 / 写评 / 收尾）  
- `send_command` **空** `output`：同命令最多再 1 次，或改一次 `interactive_session`；仍空 → **停终端**，用已有 bag/相机/负结果走结案，**禁止**停在「等待中」  
- **路径以工具入参 `command` 为准**：若 `output` 里出现 `loggs`/`ltggs`/`xzrobott_` 等怪路径，视为回显污染，不要据此改路径；空 `output` + 正确 `command` = 该次无命中  
- **最终回复红旗（立刻纠正，不得 `[done]`）：** 正文含「正在接收」「等待终端」「命令已发送」「**正在处理中**」「继续执行日志」「下一步：」且本回合已有工具返回，或仅确认了目录/`ls` 却未做时间窗抽行 → 视为计划话术收工，必须继续工具或正式结案（评论/状态）

## 产物选择

| 故障类型 / 剧本 | 优先产物 | 附件 |
|-----------------|----------|------|
| 用户指定模块 | **该模块日志** | 日志不挂附件 |
| 碰撞 / `playbook-crash` | **录包**（可辅感知日志） | 录包可挂 |
| 定位 / `playbook-locate` | **录包** + 定位日志 | 同上 |
| **行走 / 底盘 / 感知相关**（防跌落、撞障、定位漂移、雷达/相机/点云、卡滞悬空等） | 日志可抽则抽；**须**查录包 + **须**拉相关方位实时图 | **定位到包必须挂**；**相机有 url 必须挂** |
| 回站 / 对桩 / `playbook-dock` | **日志**为主（按故障域选模块）；须 happenTime 时间窗 | 按需 bag |
| 急停 / 资源 / 定时任务等（与行走感知无关或弱相关） | **日志**为主；日志空可补 bag | 按需 |
| **其它 / 未知** | 相关模块日志；偏行走感知则宜挂 bag；日志空则补 bag | 录包/相机图有 url 才挂 |

**约定：**
- 日志 = 终端只读摘录进回复/评论；**须对齐 happenTime**，不是只看「现在」
- **凡走本技能结案素材：未做时间窗抽行（或明确负结果）且该类以日志为主 = 未完成**；禁止只报当前影子/刚下发控制/只挂实时相机就宣称「远程已穷尽」
- 录包 = `find_bags_near_time` → `upload_bag_file` → `create_ticket_attachment`（可委托 `device-pull-bag`）——供人工分析**触发原因**
- **实时相机图** = `get_camera_image` → 有 `url` → `create_ticket_attachment`——供看**当前**环境；**不能代替**故障时刻 bag / 历史日志
- 不按单个 faultCode 写死是否挂附件，按现象是否涉及行走/感知判断
- **禁止自造剧本 ID**；只使用 fault-routing 表内的 `playbook-*`

### 录包步骤（需挂 bag 时）

```
find_bags_near_time(device_id, product_id, happenTime 附近)
  → 选 1～3 个最接近的切片
  →【必须】upload_bag_file → 取得 url
  →【必须】create_ticket_attachment(ticket_id, url, ...)
```

`upload_bag_file` 成功但 **`url` 为空 / `attach_ready=false`**：工具会自动再试 `uploadList`；仍无 url → **禁止**把该 bag 写进「附件已挂载」；评论必须写明「录包上传未返回 url，请人工挂载 {文件名}」。有 url → **必须** `create_ticket_attachment(name=….bag, url=…)`。  
找到切片却跳过 upload 尝试 → 视为未完成。  
找不到录包：评论写明已按何时查找、无匹配包即可。

### 实时相机图（行走/感知须做；其它按需）

```
get_camera_image(device_id, product_id, camera="前"|"下"|"后"|"左"|"右")
  → 工具把 JPEG 上传 OSS，返回 url
  →【有 url 必须】create_ticket_attachment(ticket_id, name=…jpg, url=…)
  → 结论素材注明已挂方位与文件名，交编排写评（本技能不调 create_ticket_comment）
```

| 产品 | 可用方位 | 行走/感知默认 |
|------|----------|----------------|
| SC50 / SW50 | 前、下 | `前`；防跌落/下视相关再加 `下`（≤2） |
| T810 | 前、后、左、右 | `前`；需看四周再补后/左/右之一（≤2） |

有 url 却未挂附件 → 视为未完成。失败记结论，不要扫遍所有相机。

## 日志路径

| 产品 | 数据根 | 日志根 | **默认 app** |
|------|--------|--------|--------------|
| T810 / Titan810 | `/userdata/xzrobot` | `/userdata/xzrobot/logs` | **`titan_app`** |
| SC50 / SW50 | `/opt/xzrobot` | `/opt/xzrobot/logs` | **`xzrobot_app2`** |

优先直接进上表日志根；若不存在再只读有界查找，**不要**无界扫盘。  
**仍须先全量 `ls` 日志根，再 `ls` 选定模块目录**；只对回显里**真实存在**的文件名做 grep。固件版本可能增减目录/改名，**以当场 `ls` 为准**。

### 日志文件命名（禁止臆造切片惯例）

| 产物 | 切片/命名 | 说明 |
|------|-----------|------|
| **录包 bag** | **约 2 分钟切片**；`all_` 运行包、`task_` 任务包 | **仅录包**如此；见 PROMPT |
| **模块日志** | **不是** 2 分钟切片 | **禁止**套用 bag 惯例去猜 `17-28-*`、`HH-MM-*`、按时刻分子目录 |

实机常见（SC50，以 `ls` 为准，勿当唯一格式）：
- 按日单文件：`_YYYY-MM-DD` / `_YYYY-MM-DD.txt`（常为**文件**，不是「日期目录再往下按分钟切」）
- 其它模块可能是 `info_YYYYMMDD-HHMMSS.<pid>` 等；**只有 `ls` 见到才能用**
- **禁止**推断：`xzrobot_driver2/2026-08-06/17-28-*` 这类路径；`ls` 无该层 → 写「未见该文件名」，**不得**写成「服务未生成日志 / 被重定向 / 未启动」等因果故事
- 只读与 `happenTime` **同日**（或 `ls` 中最接近当日）的文件；不要打开无关日期

### 按故障域选主查 / 辅查（泛用）

不定死「app 永远不是根因」：按**本单故障域**决定谁主谁辅。路径仍只能来自 `ls` 实况 + 默认 app 名（优先从上表实机名匹配）。

| 角色 | 含义 |
|------|------|
| **主查** | 本域最可能存过程/根因；`ls` 存在则**必须**查 |
| **辅查** | 上报/旁证；存在则尽量同批查 |
| **默认 app** | SC50/SW50=`xzrobot_app2`，T810=`titan_app`；多数域为辅查；**任务/调度域为主查** |

| 故障域（按工单名/码归类） | 主查（ls 有则必查） | 辅查 |
|---------------------------|---------------------|------|
| 急停 / 驱动 / 安全按钮类 | SC50/SW50：`xzrobot_driver2`（可兼 `driver`；**无**独立 `chassis/`）；T810：`driver` / `titan_chassis`（≤2） | **默认 app（必查）** |
| 防跌落 / 底盘 / 感知 | SC50/SW50：`visual_perception` / `robot_monitor`；T810：`perception` / `xz_perception` / `titan_chassis` / `robot_monitor`（≤2） | 默认 app |
| 定位 / slam / nav | SC50/SW50：`xzrobot_slam` / `xzrobot_3d_slam` / `xzrobot_navigaiton`；T810：`slam` / `xz_3d_slam` / `navigation`（≤2） | 默认 app |
| 对桩 / dock | T810：`dock` / `navigation`；SC50/SW50：`xzrobot_navigaiton`；可辅 `xzrobot_driver2/lora_logs`（ls 有则，≤2） | 默认 app |
| **任务 / 暂停 / 定时 / 调度 / 任务失败 / 任务暂停超时** | **仅默认 app**（SC50=`xzrobot_app2`） | **默认不查** `driver`/`xzrobot_driver2`/`navigaiton`；仅当 app 时间窗原文已点名其它模块，或工单名同时含急停/防跌落/定位时，才加 1 个辅查 |
| 未知 | 默认 app；再从 ls 挑名称与故障词接近的 **1** 个 | — |

### 任务/暂停域专项（防乱扩候选）

工单名/现象含「任务暂停」「暂停超时」「定时任务」「调度失败」等时：

| 禁止 | 必须 |
|------|------|
| 把 `xzrobot_driver2` / `driver` / `navigaiton` 标成**主查**或与 app **并列主查** | 主查**只有**默认 app；先对其做 happenTime 时间窗 |
| 因影子里另有行走码（如自造/旁路 `0x102…`）就去查 driver | 主依据仍是工单 `faultList`；旁路码最多一句旁注，**不改主查** |
| app 尚未抽完就平行开查 driver「碰运气」 | app 有摘录或明确负结果后再决定是否（通常不必）加辅查 |
| 任务单套用「急停对照附录」去翻 MCU/emergency | 急停附录**仅急停域**；任务单看默认 app 的 pause/timeout/本单码等当次回显 |

硬规则：
1. **主查在 `ls` 中存在却未做时间窗抽取 → 流程未完成**（急停漏域表主查；**任务漏默认 app**）
2. 主查不存在 → 退到辅查/默认 app，评论写明「ls 无主查目录，已查 …」
3. 候选合计 ≤3；任务域默认 **1（仅 app）**，有明确理由才到 2
4. 时间窗空 → 换下一候选或收尾；关键词空 ≠ 无日志；禁止 `tail`/`cat`/二进制臆断
5. **任务域**只查 app → **可以且应当**结案；不要写成「只查 app 不够」去扩 driver

### 关键词（仅辅，勿当主策略）

时间窗抽行之后，若需在窗内加滤或二次补查，可参考：

| 故障/模块 | 关键词示例（辅） |
|-----------|------------------|
| 急停 | `急停` `emergency` `e-stop` `ESTOP` `0x2020000A` |
| 防跌落 | `fall` `drop` `cliff` `防跌落` `gpio` `0x2020000C` |
| 相机 / 感知 | `camera` `image` `decode` `timeout` |
| 定位 | `locate` `reloc` `定位丢失` |
| 碰撞 | `collision` `crash` |
| 对桩 | `dock` `对桩` `lora` |
| 任务 / 调度 | `pause` `timeout` `task` `schedule` `定时` `暂停` |
| 通用 / app | `ERROR` `WARN` `Exception` `fail` 及本故障名/码 |

**不要**用「全文件 grep 关键词为空」代替「happenTime 附近无行」；更不要据此断言硬件根因。

## 评论证据要求（证明材料）

写回工单 / 对内汇报时，日志取证**必须带证明**，不能只有概括句或探路叙事：

1. **时间点**：与 `happenTime` 对齐的**时间窗摘录**；禁止用文件末尾最新行冒充；禁止只用「关键词全文件无匹配」充当已取证
2. **原文摘录**：时间窗命中则贴 2～5 行（**必须是工具 output 原文**，保留时间戳）；未命中则写明已 `ls` 文件名、已查时间窗与负结果——**此时零摘录，不要编**
3. **路径**：日志文件须为 `ls` 实名
4. 抽不到 happenTime 附近行：评论写明已查**主查/辅查**路径与负结果；行走/感知类 **补录包 + 尝试相机挂图** 后按结案判据改状态
5. 行走/感知评论须写明：已挂 bag 名（或无包/upload 失败原因）+ 已挂相机方位（或拉图失败原因）
6. **禁止**主查在 `ls` 有却未做时间窗；**禁止**空关键词后编硬件根因；**禁止**未贴 `ls` 就写「无日志 / 未启用」；**禁止编造任何未在工具回显中出现的日志行**
7. **自检（按故障域拆开，禁止急停规则套防跌落）：**
   - **急停**：主查（SC50 常为 `xzrobot_driver2`，以 ls/域表为准）与默认 app，ls 有则须做时间窗；未做 → 未完成
   - **防跌落 / 行走 / 感知**：按域表主查（如 `visual_perception`/`robot_monitor` 等）做时间窗 + bag/相机契约；**不得**因「急停要查 driver2」去硬套防跌落
   - **任务/暂停/定时**：主查仅默认 app；去查 driver 当主查 → 违规；已查 app → 可完成
   - 拟写摘录对不上工具 output → **不得**交编排写入评论
8. 相机错误码 / 无 bag / 关键词空 → 只记现象，**不要**写成「多重验证确认硬件失效」
9. app 上报文案若出现在工具回显中可原文引用；**仍不得**升格为「已证实物理按键」等工具未写明的因果

## 评论素材 / 回复结构

有 `ticket_id` 时：把下列**中性骨架**交给 `ticket-handling` 第五步写评（本技能不调写评工具）。  
**禁止**把下文示例句原样抄进本单评论；摘录必须来自当次工具回显。

```
【AI分析】设备 {deviceId}，工单故障「{faultName}」。
已查日志路径：{path}（或明确负结果：已 ls / 已抽 happenTime 窗无命中）。
结论：{基于工具事实的一两句}。当前无法远程修复 / 需现场处理（若适用）。已转问题分析。
关键时间点：与 happenTime 对齐的窗（或写明未命中）。
日志摘录（2～5 行，须 ⊆ 工具 output；无则写「无匹配行」）：
…
（行走/感知另附：已挂 bag 名或失败原因；已挂相机方位或失败原因）
```

无 ticket 时同样要带时间点+摘录直接回复用户。

## 注意事项

- 取证 ≠ 处置；用完终端必须断开
- 挂 bag / 相机图最多各 1～3 个；日志不编造 url；附件必须有可访问 url
- 目录不存在 / 连不上：如实说明，交编排改 `6` 结束
- **日志证据 = happenTime 时间窗短摘录**（关键词仅辅）；遵守上方取证边界原则
- **最终检查：** 有 ticket → 已按现象完成 happenTime 证据（日志窗/负结果；行走类另含 bag+相机）→ 交编排写评+改状态
- **自检红旗：** 未做时间窗只做关键词/`tail`；**只写当前影子或刚下发动作、无当时证据**；臆造路径/文件名；素材含工具从未返回的日志句；空关键词+相机错码就写「硬件已证实」；主查在 ls 有却未抽；已定位录包却只建议下载 → 立即纠正
- **零容忍：** 宁可写「无命中原文」转人工，也**禁止**编造日志摘录写回工单
- **禁止编造操作指引：** 不得杜撰技能未记载的云端/APP/设备界面点击步骤；需要现场时写「请按产品实际界面处理」
- **禁止把「连不上」写成根因：** 离线/关机/未联网/终端不可达 ≠ 驱动崩溃或模块异常；无日志回显不得写硬件/软件崩溃类结论
- **禁止双发：** 有工单时本技能绝不调用 `create_ticket_comment`
